# TerraOps Data Contract

## Default data policy
Do not depend on proprietary or paid data.

Use one of:
1. synthetic demo data generated by the repository;
2. public-domain/open-licensed datasets with documented provenance;
3. user-provided data that contains no unnecessary sensitive information.

## Demo dataset
Create deterministic synthetic data that resembles organizational resource usage over time.
Include enough history for:
- utilization trends;
- recurring patterns;
- at least one injected anomaly;
- at least one forecastable period.

Generate it with a fixed random seed.

## Factor data
Keep carbon/impact factors versioned and separate from code.
Each factor record must contain:
- factor id;
- value;
- unit;
- geography/scope;
- source;
- effective date if known;
- notes/uncertainty.

Never invent factor values. If a factor is needed for the demo and no authoritative source has been approved, make it an explicitly labeled **illustrative synthetic factor** and keep it out of any claim about real-world emissions.

## Knowledge sources
Store source metadata with each document/chunk.
Do not scrape websites automatically unless the source terms permit it and the human has approved the source.

## Data quality
Implement checks for:
- missing fields;
- invalid timestamps;
- duplicate records;
- unit mismatches;
- impossible numeric values.

Expose data quality warnings in the UI.

## Privacy
Do not collect names, email addresses, passwords, precise personal location, financial data, or other sensitive data for the MVP.

If uploaded data unexpectedly contains sensitive fields, do not log them. Warn the user that the demo expects operational data only.
